# AllinOne 开发说明

动手之前先读 [设计原则](设计原则.md)：AllinOne 是什么，每个功能该往哪个方向做。

## 结构

| 目录 | 内容 |
|---|---|
| `src/main.ts`、`src/worker.ts` | 每台电脑上常驻的主程序：角色（主电脑 / 设备）、本机控制窗口（`127.0.0.1:18812`）、托盘状态、Tailscale 引导、自动更新 |
| `src/hub/` | 主电脑：手机网页、对话记录（SQLite）、在设备之间转发命令、Agent 互通 |
| `src/device/` | 设备：各家 Agent 的适配器（`codex/`、`claude/`、`opencode/`、`goose/`），以及给 Agent 用的 MCP 工具 `mcp.ts` |
| `src/setup/` | 安装和卸载脚本（`Setup.cmd` 调用；放在 `src` 下，是为了随自动更新一起更新） |
| `web/` | 手机和浏览器里的界面，由主电脑提供 |
| `web-control/` | 每台电脑的本机控制窗口 |
| `tray/tray.ps1` | 托盘图标，并负责拉起主程序（退出码 75 重启主程序，76 连托盘一起重启） |
| `android/` | 安卓 App（一个薄壳：界面来自主电脑，原生部分负责通知、扫码、文件、离线引导） |
| `test/` | `node --test` 测试 |

## 常用命令

| 命令 | 作用 |
|---|---|
| `runtime\node\node.exe src\main.ts` | 在控制台里运行（不带托盘） |
| `runtime\node\node.exe src\main.ts devices` | 列出 tailnet 里的电脑 |
| `runtime\node\node.exe --test test\*.test.ts` | 跑测试 |
| `runtime\node\node.exe tools\build-android.mjs` | 构建手机 App，输出 `build\android\AllinOne.apk`（版本号在 `android\version.json`） |
| `powershell -File tools\package.ps1` | 打安装包 `dist\AllinOne-<版本>.zip` 和它的 `.sha256` |
| `powershell -File tools\publish.ps1 -Target 用户名@主电脑` | 把开发代码发布到自己的主电脑，其他电脑自动跟上；目标也可以写在 `data\publish.json`：`{"target": "...", "key": "私钥路径"}` |

## 约定

- **原生优先**：运行环境都在 `runtime\`（Node 24、JDK 17、Android SDK），不装进系统。第三方依赖只有主电脑用的 `ws`；二维码用 `web-control\vendor\qrcode.js` 和 `android\assets\vendor\jsQR.js`（MIT）。
- **包含中文的 `.ps1` 文件必须带 UTF-8 BOM**，否则 Windows PowerShell 5.1 解析会出错。
- **`src/update.ts` 的 `PARTS` 不能再加项**：旧版本按旧清单核对新包的指纹，加了项会拒收新包。新文件请放进已有的目录。
- 新增 Agent：完整步骤见 [接入新Agent.md](接入新Agent.md)。提交改动的约定见 [CONTRIBUTING.md](../CONTRIBUTING.md)。

## 数据和端口

- 每台电脑的数据在 `data\`：`config.json`（主电脑是哪台、本机凭据）、`hub.sqlite`（主电脑的记录，包括已读和置顶）、`device.sqlite`（设备的发件箱）、`allinone.log`。
- **一定要备份 `data\android-signing\`**：这是手机 App 的签名密钥，丢了就无法覆盖升级 App。
- 端口固定：主电脑 `127.0.0.1:18811`，经 `tailscale serve` 以 HTTPS 发布在 `18801`；本机控制窗口 `127.0.0.1:18812`。

## 不经 MCP 直接调用 Agent 接口

Agent 平时用 MCP 工具 `allinone`。脚本也可以直接 POST 到本机的 `http://127.0.0.1:18812/api/agent`，请求体写成 `{op, agent, thread, args}`：

- `op`：`agents`、`send`、`read`、`stop` 或 `wait`。
- `agent`：发起方是哪个 Agent，例如 `claude-code`。
- `thread`：发起方自己的对话编号。从 Claude 对话里启动的脚本，填环境变量 `CLAUDE_CODE_SESSION_ID`。不填的话，主电脑只能去猜是哪个对话发起的，汇报可能回到别的对话，发起方也会标错。MCP 工具会自动带上这个编号。
- `args`：参数和 MCP 工具相同。`send` 可以带 `files`（本机文件的完整路径），这些文件会传到对方电脑。失败的请求在 `wait` / `read` 的结果里带 `error`，写明原因。

## 在一台虚拟的新电脑上试

不用真的新电脑，也能把安装 → Tailscale 引导 → 主电脑 → 卸载走一遍：

- 编一个假的 `tailscale.exe`，用它目录下 `state.txt` 的内容（`stopped` / `needslogin` / `https-off` / `ready`）决定 `status --json` 和 `serve` 的输出。
- 用下面这些环境变量启动另一份程序，它就不会碰这台电脑上真实的 AllinOne：
  - `ALLINONE_TAILSCALE`：假 `tailscale.exe` 的路径；
  - `ALLINONE_DATA`：另一个数据目录；
  - `ALLINONE_CONTROL_PORT`、`ALLINONE_HUB_PORT`：换掉端口；
  - `ALLINONE_TEST=1`：不碰注册表里的开机自启。
- `ALLINONE_INSTALL_TEST=<目录>` 让 `Setup.cmd` 和卸载脚本只在这个目录里操作：不弹窗，也不碰注册表。

## 开源发布前

- `git` 历史里有开发时的机器名和地址，公开仓库时建议用新的历史（只保留当前代码）。
- `package.json` 的 `allinone.releases` 填上 GitHub 仓库（`owner/name`），主电脑就会去检查 Releases 里的新版本：每个版本上传 `AllinOne-<版本>.zip` 和 `.sha256` 两个文件。
- Codex 的接口说明在 `docs\codex-protocol\`（从 Codex 0.164 导出）。
