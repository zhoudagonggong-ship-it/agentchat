# AgentChat 设计原则

**开发任何功能、修任何问题之前，先对照这份文档。** 很多看起来像 bug 的问题，根子都在于偏离了这里写的意义。

## AgentChat 是什么

AgentChat 是**主人和一个跨电脑的 Agent 团队之间唯一的工作场所**。

- **主人是指挥者。** 主人决定做什么、交给谁做，也随时可以插话。
- **Agent 是团队成员。** 每台电脑上的 Codex、Claude Code、OpenCode、Goose，就像主人通讯录里的同事，各自在自己的电脑上干活。
- **主人自己建的对话，是真正干活的地方。** 汇报、派活、插话都发生在这里。
- **手机是主人随身带着的那扇窗。** 主人走到哪，都能看到、说上话、拍板。

## 五条原则

### 1. 同一个对话，在哪看都一样
对话真正属于电脑上那个 Agent 软件，AgentChat 只是主人远程的眼睛和手。主人在手机上说一句，效果要和他坐在那台电脑前亲手打字一模一样，电脑上当场就能看到。

- 消息一律从 Agent 自己的窗口或服务发进去。窗口暂时发不了，就排队等，**宁可等，也不绕到后台**。绕过窗口写进去，窗口里看不到，还会让对话分叉。
- 只有两种情况能走后台：那个软件根本没打开，或者对话不在它的列表里。这时没有窗口可以绕开。
- 用完就把对话交还给 Agent 自己的软件，不能占着不放。

### 2. 主人始终在场，什么都看得见
Agent 之间的往来，都发生在主人看得到的地方：主人的对话里、派活卡片上、手机上。

- 谁说的、从哪个对话来的，都要如实标注，不能靠猜。
- 报告的状态必须和实际一致。回复到了就是到了，不能报「中断」，也不能报「没有回复」。
- 需要新开对话时，开主人看得到、能参与的工作对话。只为传话的隐藏通道，只在主人不需要参与时用。
- 审批和提问永远只由主人回答。

### 3. 主人的指令说了算
护栏，包括转手上限、限频、互通开关，是用来防止 Agent 之间失控的，**绝不能拦主人亲自交代的事**。

- 主人在自己的对话里直接交代的事，算作一条新的链，从头计数。
- 被护栏拦下时，要告诉主人原因和办法，而不是让 Agent 去绕。

### 4. 团队成员要像同事一样
- 每个 Agent 都**天然知道**团队靠 AgentChat 沟通：新对话、新电脑上的 Agent 也一样，不用主人再教一遍。
- 说主人的语言（中文）。
- 有主人给起的名字和头像，可以设消息免打扰。这些都记在主电脑上，更新、重装、换手机都不会丢。

### 5. 为主人省心
- 给不懂电脑的人用：界面上不出现 IP、端口、命令行，每一步都有按钮或引导。
- 一个软件搞定，不让主人在好几个软件之间来回切。
- 能自动的都自动：加入、更新、发现新 Agent、重试。
- 出了问题，用大白话告诉主人发生了什么、该怎么办，而不是丢给他一个错误代码。

## 每次动手前问自己三个问题

1. **主人在手机上看到的，和他坐在那台电脑前看到的一样吗？**
2. **主人知道发生了什么吗？** 谁做的、做到哪了、结果是什么，都清楚吗？
3. **有没有挡住主人自己的意图？**

有一个问题答不上来，就先停下来想清楚，再动手。

## 从踩过的坑里学到的

| 发生过的事 | 违背了哪条 | 现在的做法 |
|---|---|---|
| 手机消息找不到「发送」按钮，就绕到后台发送，结果电脑上看不到，对话也分叉了 | 1 | 只在窗口里发，发不了就排队重试 |
| AgentChat 跑完一轮后一直占着 Codex 对话，桌面端没法接着写 | 1 | 没有进行中的任务时就交还 |
| 主人让 Codex 去联系别的 Agent，被「最多转 3 手」拦住 | 3 | 按主人正在用的对话计数，主人交代的事从头算 |
| 消息来源标成了另一个同时在运行的对话 | 2 | Agent 的工具带上自己所在的对话，不靠猜 |
| 回复已经到了，却报「中断、没有回复」 | 2 | 正在别处运行的那一轮按「进行中」处理，等到真正结束 |
| Agent 不知道能用 AgentChat，还用英文回答 | 4 | 工具自带说明，全局说明里写明，并写上「用中文回答」 |
| 每次打开手机都满屏红点 | 5 | 已读状态存在主电脑，只有真正的新回复才算未读 |
